# Contributing

Thanks for contributing! This monorepo has one rule above all others:

> If `Rscript scripts/build-all.R` and `Rscript scripts/lint-all.R` pass
> on your machine, CI will pass. Run them before every push.

## Setup

```r
# from the repository root
renv::restore()   # install the exact locked toolchain
```

Machine-specific notes (nix R, CachyOS, missing system libraries) live
in the README Troubleshooting section and `.Renviron`.

## Workflow

1. Branch from `main`.
2. Make your change in `packages/<pkg>/`.
3. Run the gates (or `make release-check`):

   ```sh
   Rscript scripts/build-all.R      # document, test, R CMD check, install
   Rscript scripts/lint-all.R       # lintr
   Rscript scripts/spellcheck-all.R # spelling (inst/WORDLIST)
   Rscript scripts/style-all.R      # apply styler before committing
   ```

4. Open a PR. CI runs the pipeline on R `release` and `oldrel-1`, plus
   `lint` (lintr + spelling), `style` (styler must produce zero diff),
   and `coverage` (90% hard threshold). All checks must be green.

## Code style

- The `.lintr` config at the repo root is law: 100-character lines,
  tidyverse-ish naming (`snake_case`), no trailing whitespace.
  Known linter false positives (e.g. `useDynLib`-bound symbols) get a
  scoped `# nolint: <linter>.` comment with a one-line justification.
- Run `Rscript scripts/style-all.R` (or `make style`) before committing;
  CI fails if styler would change anything.
- Documentation is spell-checked in CI (`scripts/spellcheck-all.R`).
  Genuine project terms go in `inst/WORDLIST`
  (`spelling::update_wordlist()`); typos get fixed.
- Every exported function needs roxygen documentation with `@examples`.
- Every behavior needs a testthat test — including error paths. New
  user-facing output deserves a snapshot test (`expect_snapshot`).
- User guides live in `vignettes/`; keep them knitting
  (`devtools`' Build > Render, or `rmarkdown::render()`).
- Validate inputs at the boundary and fail with actionable messages:
  prefer `` stop("`x` must be ...", call. = FALSE) `` and reuse
  `uofgcore::validate_numeric()` for numeric vectors.
- Don't edit `NAMESPACE` or `man/` by hand; they are generated by
  roxygen2 (commit the regenerated files, though). CI rejects stale
  generated files automatically.

## Adding a package

See "Adding a new package" in the [README](README.md). In short: copy a
sibling package, update `DESCRIPTION`, add `Imports:` entries for
internal dependencies (the build script resolves the order), register
the package name in `renv::settings$ignored.packages()`, and include
tests.

## Dependency changes

- New dependency on an existing package: `renv::install("pkg")`, use it,
  then `renv::snapshot()` and commit `renv.lock` together with your code.
- Do **not** add `devtools`/`usethis`/`pkgdown` to the lockfile — they
  are intentionally excluded (see ARCHITECTURE.md, "Dependency
  strategy"). Install them locally without snapshotting.
- The monthly CI schedule will surface CRAN-side breakage; address it by
  updating the affected pin rather than blanket `renv::update()` when
  possible.

## Commit messages

Short imperative subject line ("Add rolling_mean validation"), blank
line, then context if the *why* isn't obvious from the diff.
